# Brownie - Meditation & Emotion App

## Overview
iOS app built with SwiftUI combining guided meditation playback with emotion tracking and reflective journaling. Uses a custom text-based meditation script format that gets parsed into timed steps (speech, pauses, countdowns). Supports iCloud sync and background audio playback.

## Build & Run
- Open `MeditationApp.xcodeproj` in Xcode
- Target: iOS (iPhone/iPad)
- Requires: Xcode 15+, iOS 17+
- Build: `xcodebuild -project MeditationApp.xcodeproj -scheme Brownie -destination 'platform=iOS Simulator,name=iPhone 18 Pro'`

## Adding New Swift Files
New `.swift` files must be manually added to `MeditationApp.xcodeproj/project.pbxproj` in **four places**:
1. **PBXBuildFile section** — `{isa = PBXBuildFile; fileRef = ...}`
2. **PBXFileReference section** — `{isa = PBXFileReference; lastKnownFileType = sourcecode.swift; path = ...; sourceTree = "<group>"; }`
3. **PBXGroup children** — add the file ref ID to the `MeditationApp` group's children list
4. **PBXSourcesBuildPhase files** — add the build file ID to the Sources phase

IDs follow a sequential pattern: build file IDs start with `A1000012...`, file ref IDs start with `A2000012...`, incrementing the last hex digits.

## Architecture

### Meditation
- **MeditationApp.swift** - App entry point, `ContentView`: one main screen with a left panel (History + Settings) that slides out
- **MeditationModels.swift** - Core types: Pool, Gender, PronounResolver, MeditationStep, Meditation
- **MeditationParser.swift** - Parses meditation script text into Meditation steps
- **MeditationPlayer.swift** - AVSpeechSynthesizer-based playback engine (`@EnvironmentObject`). Also `ListeningHistory`, keyed by filename (no extension), on the device in UserDefaults: each `Record` has `lastPlayed`, `days` (local day "yyyy-MM-dd" to seconds, intervals split at midnight; the main record), `beforeDaily` (time counted before days were kept, from the old `olderSeconds`; counts toward `totalSeconds` and rarely played, never toward a day), and the last 24 hours' `intervals`, kept only for the long-press "last 24 hours" stat. The old shape (`olderSeconds` + intervals) still decodes: its intervals seed the days, and the next save writes the new shape. `days(atLeast:)` lists each (meditation, day) over a threshold, the playing one included
- **AudioRenderer.swift** - Audio rendering support
- **StreamingPlayer.swift** - Streaming playback support
- **MeditationListView.swift** - `MeditationShelf.home` is the main screen: it opens with Feelings, not a card but a section headed "How are you feeling?" (styled like the era and Evergreen headers, all set explicitly by `homeSectionHeaderText()` (headline, `secondaryLabel`); the check-in time and the link under the chips use `homeSectionDetailText()`, the same size and grey at regular weight, with the check-in's time at its right during a check-in; a tap opens Feelings) over the check-in's feelings as the same coloured chips as on the Feelings page, sitting on the page (`FeelingsHeader`; with no check-in, your most-felt past feelings, faded; under the chips, in or out of a check-in, one plain link, right-aligned with a chevron, that opens Feelings: "N more" when a check-in has more than 6 feelings, otherwise "Other feelings", or "Check in" with nothing to show); a chip tap taps that feeling and opens Feelings. To-dos is a toolbar button (checklist icon, badge counting open actions plus to-dos that need one) beside +; then this era's meditations and the Evergreen section (meditations in the `Evergreen` folder), always both (in each, and in last era's leftovers and a past era's page, meditations made today (by the filename's date; newest first by creation date) come first, then those played in the last 24 hours, by that listening (what their rows show), then the rest played in the last week, by their last 7 days' listening (`Record.seconds(inLastDays:at:)`), most first; the rest keep their order), each under a header that folds its section like a disclosure group (remembered in `@AppStorage`). In this era's section and last era's leftovers, rarely played meditations (under 10 minutes of listening, more than 4 days old) are hidden behind an "N Rarely Played" row that shows them until the app restarts; only meditations made since listening time was counted (`ListeningHistory.countedSince`) qualify, and one playing or brought along never hides. `.past` is a past era opened from History. Also holds `NowPlayingBar`, the now-playing bar (title, pulsing dot, time, pause, stop; a tap anywhere on it but pause and stop, which shades the whole bar edge to edge and down to the bottom while pressed (`BarPressStyle` passes the pressed state up to `NowPlayingBar`'s background), opens the playing meditation's editor through the `openNowPlaying` environment action: `ContentView` closes the panel, pops any page the panel opened (waiting for the pop), and sets `EditorRequest.shared.url`, which the home list takes to push its editor over whatever it has pushed; nothing happens if that editor is already open, and another meditation's editor is closed first; playback goes on): a full-width stripe tinted like a playing row that runs to the bottom edge. There is only one: `ContentView` lays it over the bottom of the main `NavigationStack` (not inside any page) and gives every page of the stack its height as bottom safe area (`NavigationBottomInset`, the navigation controller's `additionalSafeAreaInsets`; SwiftUI's `safeAreaPadding` on the stack didn't reach pushed pages), so pages sit above it while their backgrounds run on underneath. It shows whenever something is starting, playing or paused, the main screen included. Playing a row from the main screen drops a stand-in of the row card (`RowFlightView` in MeditationApp.swift, one linear `progress` that the view shapes into two phases) into the bar: the same card, title and all, is tossed up and falls on one parabola under constant gravity (rising toward you on a soft shadow; its time follows from the drop), then is caught at the bar's place, spreading at once into the bar's width, square corners and highlight with the bar's own live contents (`NowPlayingBarContent`, shared with the bar) coming up on it, and dips under the impact and settles; then the real bar replaces it with no crossfade. The real bar only comes in when the stand-in lands (unanimated, under it), so no blank strip opens at the bottom during the flight. From the moment it lifts off (`rowInFlight` environment value) and for as long as the bar holds it (playing or paused), the row is drawn as the gap the card came out of: no card, just the page, with its name in the bar's tint faded halfway toward the page (quieter than the other titles) and its listening time dimmed, and no dot or elapsed time, since the bar shows those. Starting another meditation while the bar is up flies nothing: the bar's title and time roll over (push from below) and the new row lights up. Stopping sinks the bar down with a fade (an explicit offset and opacity, `nowPlayingBarSinking`, ease-in 0.25s) while the pages take back its space on the same curve and timing (`NavigationBottomInset` drives the navigation controller's bottom inset frame by frame with a display link, since SwiftUI doesn't animate a UIKit safe-area change; it eases up again over 0.3s when the bar comes back, and applies at once when the bar slips in under a landed row), then removes it; the bar keeps showing what was playing until it's gone. The main screen reports its own pushes (Feelings, To-dos, editor) through `setHomePagePushed`, so a flight only starts while the main screen is in front. Pages put their own bottom controls (Feelings' Negative/Positive) in their own `safeAreaInset`, which then sits above the bar; the `nowPlayingBarShown` environment value (up and not sinking) lets them keep a wider gap over it (Feelings: 16pt, else 4pt), animated with the bar. A row's long-press menu opens with its listening stats (last 24 hours, all time, last played) from `ListeningHistory` in MeditationPlayer.swift
- **MeditationEditorView.swift** - Editor for meditation scripts, pushed from the list. One vertical scroll page, capped at a 720pt measure: the title field, then the script, then one section per pool ("well"), then + New Pool; everything scrolls together. `MedDocument` splits the text into header (title/tag lines), pools and script: the title is centered with a leaf just to its right (filled green when Evergreen), no rule under it, that opens a small menu with the Evergreen toggle, which moves the file into or out of `Evergreen/` (there are no tags any more, and old `#tags` in a header are kept but ignored); there is no ⋯ menu; `MedTextEditor` (with `scrolls: false`, so it takes its text's height and scrolls the page to keep the caret in view) edits only the script (given the rest as `outside`). Each `WellSection` sits on a faint rounded card, lined up with the title, and has its `~name` as plain semibold text, no count (dimmed and marked unused when nothing draws from it); a long press on that name row opens its options (Replace ~name with Its Text for a one-item pool, Delete Pool with a confirm), then its items as `MedItemField` rows (a `MedItemTextView`, which draws the script's chips behind times, pauses and counts, and opens the same value popover on a tap) with `MedItemMarkerMenu` (comment out, pronouns, 🪨, Delete Item), Return for the next item, and + Item. Item edits write straight into the pool block (`MedPoolBlock.text(with:)`) as you type; the section keeps its own items (stable ids while typing) and re-reads the block only when it changed elsewhere; a blank item goes when typing leaves it. Wells are ordered as the script first reaches them, depth first (a pool, then the pools its items draw from), then pools nothing reaches. Pool references are pink links with no chip (only values that open a popover sit on chips); a tap on one, in the script or in a well item (`MedItemField.onOpenPool`), scrolls to its well; New Pool… and Make Pool… (from the script or a well item) create or extend the well and scroll to it, focusing a new blank item when there was no selected text. A new well keeps a blank indented line while empty (a pool needs one), and a well still empty when typing leaves it, or when the page closes, is removed. Edits write the file back as title, pools, script, so pools gather at the top; a file is only rewritten that way once something in it is edited. + New Pool is plain centered text under the wells. Swipe a well's card left for Delete (a long swipe asks straight away). The keyboard goes away (`dismissKeyboard()`) on Play, a tap on a pool link, opening an item's or pool's menu, starting a swipe on a pool card, a tap on the page's empty space, and Return in the title. In the script, each repeat is drawn as a faint rounded box (`MedRepeatLayout` in MedQuickEdit.swift, drawn by `MedTextView`): a line ending in `×N` is a one-line box, and a `[` line through its `] ×N` line is a box around what's between, nested boxes drawn in from the right, their brackets greyed; a line with two or more repeats (`~x 7″ ×3 ‖23″ ×5`) is written out in brackets when the editor opens (not saved until something is edited, and playback carries on) and when the caret leaves it. A pause, dots or countdown that ends a line is kerned to the right edge (inside its boxes). The value popover (title and a small trash for Remove, the value, −10s −1s / +1s +10s, and a slider stepping through `MedValueEdit.sliderStops`: seconds up to 20, then coarser up to an hour) replaces quick picks, and the keyboard bar's timer menu adds a pause, countdown or break at the caret or a repeat at the end of the line, then opens its popover. Play is a round floating button at the bottom right that tries the script as it stands; it shows only while the now-playing bar is down, since pause and stop are on the bar. Opening the editor of the meditation that's playing leaves it playing (and it keeps going after Back); opening any other meditation's editor stops what's playing, so the bar never shows one script under another. An edit stops only this script. Play saves first, so a new meditation gets its file and row, and the player records the listening under the file's current name. Autosaves about a second after typing stops, and on leaving the page or the app; no Save button. There is no filename field: the file is named `date-title-slug` from the title (`MedFilename`) and follows title edits, for a new meditation or one whose name still matches its title and has no store link; there is no way to rename it by hand in the app any more. A rename renames the file where it is (`MeditationLibrary.rename`) and carries its eras, listening stats and store link along; a name another meditation in any folder already has is saved as `name-2` (etc.) instead of writing over it
- **MedTextEditor.swift** - Custom text editor component (UITextViewRepresentable). A tap on a time, repeat count, pool reference, a whole pool definition or the title line opens a quick edit instead of placing the cursor; tappable text sits on a rounded chip (`MedTextView`), and each pool definition is folded into one row (`MedFold`): its `~name` line on a full-width chip with an item count (dimmed and marked unused when nothing draws from it), its item lines and any blank lines before the next pool drawn at no height. The text keeps every line; the caret skips folded text, and Return at a pool row starts a line under the whole pool
- **MedQuickEdit.swift** - Quick edits for the editor: finds tappable times/counts/pools on a line, the value popover, `MedPoolBlock` (reads a pool block and rewrites it from items), `MedItemMarkerMenu` (an item's options: pronouns, 🪨 weight, comment out as `# item`), and `MedPoolEditorSheet`, the pool sheet now used only for a pool defined inside text that `MedTextEditor` edits whole (the meditation editor shows pools as wells instead). New Pool… in the keyboard bar's ~ menu asks for a name and puts `~name` at the caret; in the meditation editor the pool becomes a new well. Make Pool… in the edit menu for selected text (in the script or in a pool item) puts `~name` in its place and makes the text an item of that pool (a new one, or one more item of an existing one); trailing pauses and times stay where they were. A pool with one live item has Replace ~name with Its Text, which writes the item over every reference and removes the pool (not offered when a pick from it is remembered or it's defined twice)
- **SettingsView.swift** - App settings (voice selection, speaking rate, iCloud), and Export Journal (a ShareLink of `JournalExport.markdown`, the whole journal as Markdown; shown once there is a past entry)
- **EraIndex.swift** - Eras: unnamed stretches of time in `eras.json` (id, start date, and `kept`; each era's folder is named by its start date, `-2` for a second one that day). A meditation belongs to the era it was made in and any era it was brought along to (`eras(of:)`: its folder, its date, `kept`); nothing about eras is in the scripts. Start a New Era is in the + menu; the previous era's leftovers sit folded at the bottom of the main screen with Bring Along in the long-press menu, and past eras open from History

### Widgets
- **BrownieWidget/** - The widget extension target (`BrownieWidgetExtension`, bundle id `com.joeedelman.meditations.widget`): Quick Play (small: the last played meditation; medium: four recent ones; a tap plays through `PlayMeditationIntent`) and Today (small and medium: today's check-in feelings, or "How are you feeling?" with none today; minutes listened today; listening this era, and on medium the era's most-listened meditation; a tap opens Feelings through `brownie://feelings`). Its Swift files go in the widget target's own Sources phase
- **WidgetShared.swift** - In both targets: the App Group (`group.com.joeedelman.meditations`), `WidgetSnapshot` (JSON the app writes there, the widget only reads), and `PlayMeditationIntent`, an `AudioPlaybackIntent`, so the system runs it in the app's process and plays on `MeditationPlayer.shared`. `WidgetPlayHandler` is defined twice: for real in WidgetSync.swift (app), as a no-op in BrownieWidget.swift
- **WidgetSync.swift** - App only: builds the snapshot (recently played from `ListeningHistory.recentlyPlayed`, filled with this era's newest; today's feelings, from the check-in under way or today's last one; today's and this era's listening) and reloads the widgets, on scene phase changes and when playback starts or stops

### Colors
- `BackgroundColor` is plain white/black for the main screen and everything pushed from it; the left panel and its pages (History, Settings, past eras, Archived, Leaderboard) use the warmer `PanelBackgroundColor`
- **SampleMeditations.swift** - Installs the store's featured meditations for brand-new local libraries
- **MeditationStore.swift** - CloudKit public-database store: browse, download, share, updates, reports. Local file ↔ record links live in UserDefaults
- **MeditationStoreView.swift** - Store sheet (opened from the Meditations plus menu or the empty-library screen) and the Share to Store sheet

### Store backend (outside the app)
- **cloudkit/schema.ckdb** - CloudKit public-database schema (record types, indexes, security roles). Change it alongside any new store field
- **tools/cloudkit.sh** - `cktool` wrapper: import the schema to Development, feature a starter
- **web/** - med.nxhx.org on Vercel (`api/page.js`, page logic in `src/pages.js`): `/m/<id>` link pages with social cards, `/m/<id>.med` raw scripts, and the apple-app-site-association file for universal links
- **FileManager+Meditations.swift** - File persistence and iCloud migration; `meditationFiles()`, `saveMeditation` (a new one goes into the current era's folder) and archive/delete go through `MeditationLibrary`
- **MeditationLibrary.swift** - The library's layout (see SYNTAX.md, "The library folder"): scripts in folders by where they show (the folder of the latest era they belong to, named by its start date; `Evergreen/`; `Archive/`; `Older/` for before the first era). No index file: the filename's date says the era it was made in, and eras.json's `kept` lists only eras a script belongs to beyond that and its folder's (`EraIndex.eras(of:)` works it out). The filename (no extension) stays the key for listening history, store links and journal marks (`id(for:)`); an in-app rename moves the file where it is and carries eras, history and store link along. `sync()` (run before each list load) files scripts left at the top into the current era and renames clashing names with `-2`. Bring Along, Send Back, Evergreen and archive move the file and tell the player (`onMove`). tools/sort-library is the one-off Mac script that sorted the old flat folder; tools/library-test tries the moves on a copy

### Emotion Tracking
- **EmotionModels.swift** - `Emotion` struct (name, emoji, question, category), `JournalEntry`, static lists of ~45 emotions
- **EmotionStore.swift** - `@Observable` class managing session emotion counts and persisted journal entries (JSON in Documents)
- **CheckInView.swift** - Emotion selection grid with tap-to-increment counts; emotions sort by count. Pushed from the Feelings heading or a chip on the main screen
- **ReflectionView.swift** - Old free-text reflection form, unused while the to-do experiment runs
- **FeelingTodoView.swift** - Experimental to-do form (feel it through; complaint/honor, long-term value, one local action). Opened by swiping a chip left or from the To-dos page. `FeelingTodo` lives in EmotionModels.swift and persists separately in Documents/feeling_todos.json, so removing the experiment leaves the journal file alone. A to-do belongs to one feeling in one check-in session (`sessionStartedAt`, plus `sessionFeelings`, the run of feelings that session), not to the feeling for all time: a chip shows and opens only its to-do from the current session, and the Current list opens to-dos by id
- **JournalView.swift** - The left panel: History (streak, then one rounded, lightly shaded card of links (`PanelNavLabel`: icon, title, chevron): Emotion Leaderboard (chart.bar; most time first, no toggles) and under it Past Eras (clock.arrow.circlepath; only when there are past eras) opening `PastErasView` (each past era newest first, then before the first era: its date range, its number of meditations in gray, and its most-listened meditation's title when there's listening; a tap pushes that era's page; `EraIndex.pastFiles` decides what an era lists, for this and the era page alike), past entries (journal entries merged with done to-dos) under day headers ("Today", "Yesterday", "Tue 24 Nov"; subheadline semibold in `secondaryLabel`, a gap above each), each day's rows together on one rounded card in the link card's grey (`panelTileFill`, via `panelCard`) with thin inset dividers between rows, the headings on the page itself, one line per row, each ending in the same fixed-width slot (`PanelRowLabel`: a chevron when it opens a page, a play glyph for a long listen that plays, else empty) so all times share one right edge (`PastRowLine`: check-in "😠 😢 🙏" with its engaged time, done to-do "<first action>" with its feeling's emoji, meditation "<title>", reflection "<emoji> <name>", and a long listen "<meditation title>" with that day's listening time (one per meditation per day with at least `PastRow.longListenSeconds`, 30 minutes, ordered by the day's last play; its title from the file, here or archived, else the filename; a tap closes the panel and, once it's shut (the `closePanel` environment action's completion), plays it (unless it's already the one playing), so the bar comes up as it does from the main screen (the row drops into it if it's on screen) instead of during the slide; with its file gone the row isn't tappable); durations read "45s", "38m", "1h 38m", "2h" (`JournalTimeFormatter`, also used by the leaderboard, check-in details and export); the time sits right-aligned in subheadline secondary text with monospaced digits; each feeling's emoji (a check-in's, a to-do's on the right, a reflection's) sits on its own small rounded `EmotionTile` filled with a lighter shade of that feeling's `Emotion.chipColor` (the colour of its chips on the Feelings page and the home header, mixed with white: 35% in light mode, 12% in dark, since the full colour reads heavy that small), lighter still at the top, or a neutral tile for a feeling no longer in `Emotion.all`, and no emoji marks the kind of row), no dates on rows and no swipe to delete; a tap opens the row's details on the main screen (`DoneTodoDetailView` with Reopen, `ReflectionDetailView`, `CheckInSessionDetailView`; a helpful meditation has none)), with Settings (gear) as its one toolbar button, on the left. Also `TodosView`, the To-dos page (open actions and to-dos that need an action), built from `OpenTodosSection`

## Navigation
- No tab bar. `ContentView` shows one `MeditationListView(shelf: .home)` in a `NavigationStack`, with a second `NavigationStack` (JournalView: History) behind it on the left. The sidebar button (`openPanel` environment action) or a swipe from the left edge (`PanelEdgePan`, a UIKit edge-pan on the main navigation controller, only while the main screen is the top page) slides the main screen right; a tap or leftward drag on it closes the panel, and so does a leftward swipe anywhere on the panel itself, rows included (`PanelClosePan`, a UIKit pan on the panel's navigation controller that only begins for mostly-horizontal leftward motion, runs alongside the list's scrolling and stops it once it begins; it drives the same drag offset and commit threshold as the main screen's drag, and a tap on a row still opens it; while it runs it turns the list's scrolling off). The drag offset lives in `PanelDrag`, an @Observable read only by the `PanelSlide` modifier on the main screen, so following a finger re-renders only that modifier: as `ContentView` state it re-ran `ContentView.body` every frame, whose fresh environment closures (`openFromPanel`, `openPanel`, ...) re-rendered JournalView and the main screen too. Meditation rows on the main screen have no leading swipe, so they don't fight that edge swipe; Eras… is in the long-press menu. Settings is a gear button on the left of the panel's toolbar
- The panel's pages (Settings, Emotion Leaderboard, Past Eras, a past era, a past check-in, a done to-do, an old reflection) open on the main screen, not inside the panel: the panel calls the `openFromPanel` environment action with a `PanelPage`, which closes the panel and sets the main `NavigationStack`'s path. Rows there are Buttons (`PanelLinkLabel`), not NavigationLinks
- The main screen has no title or filter menu: it always shows everything, and the era and Evergreen section headers collapse and expand their sections
- The Store and new-era sheets are presented from `MeditationListView`, and `MeditationEditorView` is pushed from it; store links open on the main screen
- `FeelingTodoView` is pushed with `.navigationDestination(item:)` from CheckInView and from TodosView

## Key Patterns
- `@EnvironmentObject` for sharing `MeditationPlayer` across views
- `@Observable` + `.environment()` for sharing `EmotionStore` across views
- Meditation scripts are plain text `.med` files stored in Documents/Meditations (or iCloud container)
- Journal entries are persisted as JSON in Documents/emotion_journal.json
- The parser converts script text → [MeditationStep] for the player
