# Brownie - Meditation & Emotion App

## Overview
iOS app built with SwiftUI combining guided meditation playback with emotion tracking and reflective journaling. Uses a custom text-based meditation script format that gets parsed into timed steps (speech, pauses, countdowns). Supports iCloud sync and background audio playback.

## Build & Run
- Open `MeditationApp.xcodeproj` in Xcode
- Target: iOS (iPhone/iPad)
- Requires: Xcode 15+, iOS 17+
- Build: `xcodebuild -project MeditationApp.xcodeproj -scheme Brownie -destination 'platform=iOS Simulator,name=iPhone 18 Pro'`

## Adding New Swift Files
New `.swift` files must be manually added to `MeditationApp.xcodeproj/project.pbxproj` in **four places**:
1. **PBXBuildFile section** — `{isa = PBXBuildFile; fileRef = ...}`
2. **PBXFileReference section** — `{isa = PBXFileReference; lastKnownFileType = sourcecode.swift; path = ...; sourceTree = "<group>"; }`
3. **PBXGroup children** — add the file ref ID to the `MeditationApp` group's children list
4. **PBXSourcesBuildPhase files** — add the build file ID to the Sources phase

IDs follow a sequential pattern: build file IDs start with `A1000012...`, file ref IDs start with `A2000012...`, incrementing the last hex digits.

## Architecture

### Meditation
- **MeditationApp.swift** - App entry point, `ContentView`: one main screen with a left panel (History + Settings) that slides out
- **MeditationModels.swift** - Core types: Pool, Gender, PronounResolver, MeditationStep, Meditation
- **MeditationParser.swift** - Parses meditation script text into Meditation steps
- **MeditationPlayer.swift** - AVSpeechSynthesizer-based playback engine (`@EnvironmentObject`)
- **AudioRenderer.swift** - Audio rendering support
- **StreamingPlayer.swift** - Streaming playback support
- **MeditationListView.swift** - `MeditationShelf.home` is the main screen: it opens with Feelings, not a card but a large heading and the check-in's feelings as the same coloured chips as on the Feelings page, sitting on the page (`FeelingsHeader`; with no check-in, your most-felt past feelings, faded); a chip tap taps that feeling and opens Feelings. To-dos is a toolbar button (checklist icon, badge counting open actions plus to-dos that need one) beside +; then this era's meditations and the Evergreen section (meditations tagged `timeless`), always both, each under a header that folds its section like a disclosure group (remembered in `@AppStorage`). In this era's section and last era's leftovers, rarely played meditations (under 10 minutes of listening, more than 4 days old) are hidden behind an "N Rarely Played" row that shows them until the app restarts; only meditations made since listening time was counted (`ListeningHistory.countedSince`) qualify, and one playing or brought along never hides. `.past` is a past era opened from History. Also holds `NowPlayingBar`, the now-playing bar (title, pulsing dot, time, pause, stop): a full-width stripe tinted like a playing row that runs to the bottom edge. There is only one: `ContentView` lays it over the bottom of the main `NavigationStack` (not inside any page) and gives the stack its height as bottom `safeAreaPadding`, so pages sit above it while their backgrounds run on underneath. It shows whenever something is starting, playing or paused, the main screen included. Playing a row from the main screen drops a stand-in of the row card (`RowFlightView` in MeditationApp.swift, one linear `progress` that the view shapes into two phases) into the bar: the same card, title and all, is tossed up and falls on one parabola under constant gravity (rising toward you on a soft shadow; its time follows from the drop), then is caught at the bar's place, spreading at once into the bar's width, square corners and highlight with the bar's own live contents (`NowPlayingBarContent`, shared with the bar) coming up on it, and dips under the impact and settles; then the real bar replaces it with no crossfade. The real bar only comes in when the stand-in lands (unanimated, under it), so no blank strip opens at the bottom during the flight. While it's away the row is faded a little (`rowInFlight` environment value), then takes its playing look: card colour with a thin accent outline and no elapsed time, since the bar shows it. Starting another meditation while the bar is up flies nothing: the bar's title and time roll over (push from below) and the new row lights up. Stopping sinks the bar down with a fade (an explicit offset and opacity, `nowPlayingBarSinking`), then removes it and the pages take back its space; the bar keeps showing what was playing until it's gone. The main screen reports its own pushes (Feelings, To-dos, editor) through `setHomePagePushed`, so a flight only starts while the main screen is in front. Pages put their own bottom controls (Feelings' Negative/Positive) in their own `safeAreaInset`, which then sits above the bar. A row's long-press menu opens with its listening stats (last 24 hours, all time, last played) from `ListeningHistory` in MeditationPlayer.swift
- **MeditationEditorView.swift** - Editor for meditation scripts, pushed from the list. One vertical scroll page, capped at a 720pt measure: the title field, then the script, then one section per pool ("well"), then + New Pool; everything scrolls together. `MedDocument` splits the text into header (title/tag lines), pools and script: Evergreen, Tags… and Rename File… are in the title bar's ⋯ menu; `MedTextEditor` (with `scrolls: false`, so it takes its text's height and scrolls the page to keep the caret in view) edits only the script (given the rest as `outside`). Each `WellSection` sits on a faint rounded card, lined up with the title, and has its `~name` as plain semibold text, no count (dimmed and marked unused when nothing draws from it); a long press on that name row opens its options (Replace ~name with Its Text for a one-item pool, Delete Pool with a confirm), then its items as `MedItemField` rows (a `MedItemTextView`, which draws the script's chips behind times, pauses and counts, and opens the same value popover on a tap) with `MedItemMarkerMenu` (comment out, pronouns, 🪨, Delete Item), Return for the next item, and + Item. Item edits write straight into the pool block (`MedPoolBlock.text(with:)`) as you type; the section keeps its own items (stable ids while typing) and re-reads the block only when it changed elsewhere; a blank item goes when typing leaves it. Wells are ordered as the script first reaches them, depth first (a pool, then the pools its items draw from), then pools nothing reaches. Pool references are pink links with no chip (only values that open a popover sit on chips); a tap on one, in the script or in a well item (`MedItemField.onOpenPool`), scrolls to its well; New Pool… and Make Pool… (from the script or a well item) create or extend the well and scroll to it, focusing a new blank item when there was no selected text. A new well keeps a blank indented line while empty (a pool needs one), and a well still empty when typing leaves it, or when the page closes, is removed. Edits write the file back as title, pools, script, so pools gather at the top; a file is only rewritten that way once something in it is edited. + New Pool is plain centered text under the wells. Swipe a well's card left for Delete (a long swipe asks straight away). The keyboard goes away (`dismissKeyboard()`) on Play, a tap on a pool link, opening an item's or pool's menu, starting a swipe on a pool card, a tap on the page's empty space, and Return in the title. Play is a round floating button at the bottom right that tries the script as it stands; it shows only while the now-playing bar is down, since pause and stop are on the bar. Opening the editor of the meditation that's playing leaves it playing (and it keeps going after Back); opening any other meditation's editor stops what's playing, so the bar never shows one script under another. An edit stops only this script. Play saves first, so a new meditation gets its file and row, and the player records the listening under the file's current name. Autosaves about a second after typing stops, and on leaving the page or the app; no Save button. There is no filename field: the file is named `date-title-slug` from the title (`MedFilename`) and follows title edits, for a new meditation or one whose name still matches its title and has no store link; Rename File… in the ⋯ menu names it by hand and stops that. A rename moves the file (and its era, listening stats and store link) instead of leaving a copy; a name another meditation already has is saved as `name 2` (etc.) instead of writing over it
- **MedTextEditor.swift** - Custom text editor component (UITextViewRepresentable). A tap on a time, repeat count, pool reference, a whole pool definition or the title line opens a quick edit instead of placing the cursor; tappable text sits on a rounded chip (`MedTextView`), and each pool definition is folded into one row (`MedFold`): its `~name` line on a full-width chip with an item count (dimmed and marked unused when nothing draws from it), its item lines and any blank lines before the next pool drawn at no height. The text keeps every line; the caret skips folded text, and Return at a pool row starts a line under the whole pool
- **MedQuickEdit.swift** - Quick edits for the editor: finds tappable times/counts/pools on a line, the value popover, `MedPoolBlock` (reads a pool block and rewrites it from items), `MedItemMarkerMenu` (an item's options: pronouns, 🪨 weight, comment out as `# item`), and `MedPoolEditorSheet`, the pool sheet now used only for a pool defined inside text that `MedTextEditor` edits whole (the meditation editor shows pools as wells instead). New Pool… in the keyboard bar's ~ menu asks for a name and puts `~name` at the caret; in the meditation editor the pool becomes a new well. Make Pool… in the edit menu for selected text (in the script or in a pool item) puts `~name` in its place and makes the text an item of that pool (a new one, or one more item of an existing one); trailing pauses and times stay where they were. A pool with one live item has Replace ~name with Its Text, which writes the item over every reference and removes the pool (not offered when a pick from it is remembered or it's defined twice)
- **SettingsView.swift** - App settings (voice selection, speaking rate, iCloud), and Export Journal (a ShareLink of `JournalExport.markdown`, the whole journal as Markdown; shown once there is a past entry)
- **EraIndex.swift** - Eras: unnamed stretches of time in `eras.json` (start date, plus meditations brought along by filename). A meditation belongs to the era it was made in and any era it was brought along to; nothing about eras is in the scripts (old `#era` tags are migrated out on load). Start a New Era is in the + menu; the previous era's leftovers sit folded at the bottom of the main screen with Bring Along in the long-press menu, and past eras open from History

### Colors
- `BackgroundColor` is plain white/black for the main screen and everything pushed from it; the left panel and its pages (History, Settings, past eras, Archived, Leaderboard) use the warmer `PanelBackgroundColor`
- **SampleMeditations.swift** - Installs the store's featured meditations for brand-new local libraries
- **MeditationStore.swift** - CloudKit public-database store: browse, download, share, updates, reports. Local file ↔ record links live in UserDefaults
- **MeditationStoreView.swift** - Store sheet (opened from the Meditations plus menu or the empty-library screen) and the Share to Store sheet

### Store backend (outside the app)
- **cloudkit/schema.ckdb** - CloudKit public-database schema (record types, indexes, security roles). Change it alongside any new store field
- **tools/cloudkit.sh** - `cktool` wrapper: import the schema to Development, feature a starter
- **web/** - med.nxhx.org on Vercel (`api/page.js`, page logic in `src/pages.js`): `/m/<id>` link pages with social cards, `/m/<id>.med` raw scripts, and the apple-app-site-association file for universal links
- **FileManager+Meditations.swift** - File persistence and iCloud migration

### Emotion Tracking
- **EmotionModels.swift** - `Emotion` struct (name, emoji, question, category), `JournalEntry`, static lists of ~45 emotions
- **EmotionStore.swift** - `@Observable` class managing session emotion counts and persisted journal entries (JSON in Documents)
- **CheckInView.swift** - Emotion selection grid with tap-to-increment counts; emotions sort by count. Pushed from the Feelings heading or a chip on the main screen
- **ReflectionView.swift** - Old free-text reflection form, unused while the to-do experiment runs
- **FeelingTodoView.swift** - Experimental to-do form (feel it through; complaint/honor, long-term value, one local action). Opened by swiping a chip left or from the To-dos page. `FeelingTodo` lives in EmotionModels.swift and persists separately in Documents/feeling_todos.json, so removing the experiment leaves the journal file alone. A to-do belongs to one feeling in one check-in session (`sessionStartedAt`, plus `sessionFeelings`, the run of feelings that session), not to the feeling for all time: a chip shows and opens only its to-do from the current session, and the Current list opens to-dos by id
- **JournalView.swift** - The left panel: History (streak, an Emotion Leaderboard row (most time first, no toggles), past eras, past entries (journal entries merged with done to-dos) under day headers ("Today", "Yesterday", "Tue 24 Nov"), one line per row (`PastRowLine`: check-in "🪷 😠 😢 🙏 · 12m", done to-do "✓ <first action> · 😠", meditation "🧘 <title>", reflection "<emoji> <name>"), no dates on rows and no swipe to delete; a tap opens the row's details on the main screen (`DoneTodoDetailView` with Reopen, `ReflectionDetailView`, `CheckInSessionDetailView`; a helpful meditation has none)), with Settings (gear) as its one toolbar button. Also `TodosView`, the To-dos page (open actions and to-dos that need an action), built from `OpenTodosSection`

## Navigation
- No tab bar. `ContentView` shows one `MeditationListView(shelf: .home)` in a `NavigationStack`, with a second `NavigationStack` (JournalView: History) behind it on the left. The sidebar button (`openPanel` environment action) or a swipe from the left edge (`PanelEdgePan`, a UIKit edge-pan on the main navigation controller, only while the main screen is the top page) slides the main screen right; a tap or leftward drag on it closes the panel, and so does a leftward swipe anywhere on the panel itself, rows included (`PanelClosePan`, a UIKit pan on the panel's navigation controller that only begins for mostly-horizontal leftward motion, runs alongside the list's scrolling and stops it once it begins; it drives the same `dragOffset` and commit threshold as the main screen's drag, and a tap on a row still opens it). Meditation rows on the main screen have no leading swipe, so they don't fight that edge swipe; Eras… is in the long-press menu. Settings is a gear button in the panel's toolbar
- The panel's pages (Settings, Emotion Leaderboard, a past era, a past check-in, a done to-do, an old reflection) open on the main screen, not inside the panel: the panel calls the `openFromPanel` environment action with a `PanelPage`, which closes the panel and sets the main `NavigationStack`'s path. Rows there are Buttons (`PanelLinkLabel`), not NavigationLinks
- The main screen has no title or filter menu: it always shows everything, and the era and Evergreen section headers collapse and expand their sections
- The Store and new-era sheets are presented from `MeditationListView`, and `MeditationEditorView` is pushed from it; store links open on the main screen
- `FeelingTodoView` is pushed with `.navigationDestination(item:)` from CheckInView and from TodosView

## Key Patterns
- `@EnvironmentObject` for sharing `MeditationPlayer` across views
- `@Observable` + `.environment()` for sharing `EmotionStore` across views
- Meditation scripts are plain text `.med` files stored in Documents/Meditations (or iCloud container)
- Journal entries are persisted as JSON in Documents/emotion_journal.json
- The parser converts script text → [MeditationStep] for the player
